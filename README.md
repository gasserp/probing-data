# probing-data

This public repository contains immutable acceptance state and generated
telemetry rollups from registered [`gasserp/probing`](https://github.com/gasserp/probing)
collectors. Every published value is labeled **self-reported suspected probes**.

## Trust and privacy boundary

An Ed25519 signature proves that the registered collector key signed a
canonical batch. It does not prove that an event happened, identify who
controlled an IP address, establish intent, or show compromise or abuse.
Classifier rules can produce false positives.

For accepted promoted observations, the rollups intentionally publish the top
100 exact values per period for:

- source IP addresses, without truncation or hashing;
- attempted SSH usernames; and
- eligible HTTP request paths, after query strings and fragments have been
  removed.

Paths and usernames remain potentially personal or hostile text. The collection
contract excludes passwords, successful login identities, request bodies,
headers, cookies, query strings, fragments, and ordinary HTTP paths. Eligible
paths must satisfy the configured response-status and suspected-probe signature
rules and must not match legitimate-route or sensitive-content exclusions.

## Repository layout

```text
registry/sources.json
data/acceptance-ledger.json
data/quarantine.json
data/rollups/hourly.json
data/rollups/daily.json
data/rollups/monthly.json
data/rollups/yearly.json
```

`registry/sources.json` is the reviewed, hand-authored trust registry. All files
under `data/` are generated by the pinned `probing-ingest` validator. Do not edit
the ledger, quarantine metadata, or rollups by hand.

Signed source envelopes are immutable Azure blobs named:

```text
<source_id>/<source_epoch>/<decimal-sequence-digit-count>-<canonical-decimal-sequence>/<payload-sha256>.json
```

Raw envelopes are not copied into Git. The acceptance ledger records the
immutable identity `(source_id, source_epoch, sequence)`, payload hash,
deterministic blob name, provenance, and compact accumulators. Accepted Azure
blobs are deleted only after the corresponding Git commit is pushed; otherwise
Azure's 30-day lifecycle rule eventually removes them. Exact-envelope archival
is not promised.

UTC hourly buckets generate hourly, daily, monthly, and yearly rollups. Normal
commit latency is one hour plus up to the classifier finality window, uploader
poll interval, the next hourly ingestion run, and workflow runtime. Downstream
presentation can add its own refresh interval. Delays and sequence gaps remain
visible instead of silently dropping data.

## Ingestion and quarantine

`.github/workflows/ingest.yml` runs hourly and on manual dispatch, only from
`main`. It builds `probing-ingest` from the immutable reviewed
`gasserp/probing` commit recorded in the workflow and uses GitHub OIDC for
Azure. It never uses account keys, SAS values, PATs, or publication secrets.
Before downloading, it enforces the validator's 256-file and 64 MiB input
bounds. Candidate names are never interpreted by a shell or allowed to escape
the runner's temporary input directory.

The workflow commits and pushes generated files before deleting any source
blob. It deletes only exact blob names listed by the validator in
`accepted.json`, one at a time. A crash before deletion is a safe,
byte-identical replay on the next run.

Invalid, unknown, disabled, conflicting, or otherwise rejected candidates add
only bounded metadata to `data/quarantine.json`: relative filename, size,
SHA-256, and reason code. Hostile batch content is never copied there.
Quarantined blobs remain in Azure until lifecycle expiry. If valid data and
quarantines occur together, valid generated data is pushed and accepted blobs
are cleaned up before the workflow deliberately fails visibly.

## Bootstrap and required configuration

The initial registry contains no sources. The scheduled workflow validates the
empty repository locally but skips Azure login and download until a reviewed
entry has `enabled: true`; it cannot accidentally accept a placeholder source.

Before enabling the first source:

1. Persist the collector's lowercase UUID source epoch and generated Ed25519
   private key. Never reset sequence zero within an existing epoch.
2. Convert the generated public PEM to raw 32-byte base64url without padding:

   ```sh
   openssl pkey -pubin -in source-public-key.pem -outform DER |
     tail -c 32 |
     basenc --base64url |
     tr -d '='
   ```

3. Add a reviewed registry entry using source ID
   `gasserp-azure-weu-01`, key ID `gasserp-azure-weu-01-ed25519-1`, the
   persistent epoch, the converted public key, and blob prefix
   `gasserp-azure-weu-01/<epoch>/`. Set `enabled` to `true` only when the
   collector and Azure identity are ready.
4. Configure these GitHub repository variables from the
   `gasserp/probing` Bicep outputs:

   | Variable | Bicep output |
   |---|---|
   | `AZURE_CLIENT_ID` | `githubClientId` |
   | `AZURE_TENANT_ID` | `githubTenantId` |
   | `AZURE_SUBSCRIPTION_ID` | `githubSubscriptionId` |
   | `PROBING_STORAGE_ACCOUNT` | `storageAccountName` |
   | `PROBING_STORAGE_CONTAINER` | `storageContainerName` |
   | `PROBING_STORAGE_RESOURCE_GROUP` | `resourceGroupName` |

5. Keep the Azure federated subject exactly
   `repo:gasserp/probing-data:ref:refs/heads/main` and grant its identity
   `Storage Blob Data Contributor` only on the batch container.
6. Ensure repository and organization Actions policy permits this workflow's
   explicit `id-token: write` and `contents: write`, and that `main` permits the
   workflow's authenticated push. A rejected push stops cleanup, leaving blobs
   for a safe replay.

## Emergency disable and revocation

To stop future acceptance immediately, merge a reviewed registry change that
sets the source's `enabled` field to `false`. Later blobs from that source will
quarantine rather than enter the ledger. Revoke the Azure identity separately
when compromise is suspected.

Planned key rotation requires the protocol's old-key/new-key authorization.
Lost-key recovery creates a new reviewed source epoch and key, with an explicit
continuity break; never reuse or reset the old epoch. Disabling or replacing a
registry entry does not rewrite accepted history, and removing public Git data
cannot guarantee deletion from existing clones or forks.
